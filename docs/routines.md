# Routine prompts (claude.ai scheduled routines)

Two routines run on Ron's personal claude.ai plan against this repo. Registration is not execution: after creating one, set `data/health/sessions.json → routine_status.<name> = "REGISTERED"`; the first session to observe an evidenced fire (ledger line + commit) flips it to `"LIVE"` with the commit hash. The weekly smoke workflow watches for a LIVE radar going silent.

Wording rule (learned in Ron's system, binding): a repo-writing routine prompt is framed as the user's own standing authorized routine and never contains any instruction that could read as suppressing a notification channel.

## Hard-won operational rules (from the first real fires, 2026-08-29)

1. **Clone via add_repo, not plain git.** The cloud sandbox has no git credentials: a bare `git clone` fails with `could not read Username`. Call `mcp__Claude_Code_Remote__add_repo` (owner Ronkimhi, repo upstream, access push) first, then ONE inline `git clone --depth 1`, then `register_repo_root`.
2. **Commit and push BEFORE attempting the artifact republish.** In routine venues the publish can block on a permission prompt and strand the whole run. The first radar test fire wrote three real signal cards, validated, rebuilt the UI, and then froze on the publish prompt with nothing committed. Push first; republish last; a skip is normal.
3. **A blocked republish is not a failed run.** Record `artifact: skipped(<reason>)` and finish. The repo stays canonical; the next session that can publish refreshes the page.
4. **Triage artifact-changed notifications before spending a read.** The version string in the notification (`1788027370-1843`) is a **unix timestamp** plus a hash. Two rules, one safe and one only a hint:
   - **SAFE, use it: a version timestamp LOWER than the last version you verified is an out-of-order replay.** Skip it entirely. Two of 2026-08-29's notifications were replays of already-superseded versions.
   - **HINT ONLY, never skip a read on it: the gap between the version timestamp and the page's own `built_at`.** A click republishes the page from the browser with only the queue block changed, so `built_at` does not move and the gap is *hours* (the one real click measured 2h39m: published 18:16:10Z carrying `built_at 15:37Z`). A build republish publishes minutes after its build, but *how many* minutes is the postlude's push-retry time, not a constant: measured gaps were 2, 2 and **6.7** minutes. An earlier version of this rule used a 5-minute threshold and misclassified that 6.7-minute build as a click.
   - **The queue block is the only ground truth, but a read AFTER someone else's republish proves nothing.** Every build writes `{"v":1,"queue":[]}`, so a publish erases any click queued since the last build. The drainer reading afterwards sees an empty queue whether or not a click was destroyed. This is why CLAUDE.md's click-queue step 5 puts the check on the PUBLISHER: it is the only actor positioned to see the entry before it is overwritten. Reads by the drain seat catch only clicks that arrive after the most recent publish.
